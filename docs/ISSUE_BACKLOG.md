# Engineering backlog — ordered by expected impact

Priorities combine breadth, severity, evidence, effort and regression risk. An open upstream issue is a report, not confirmation that the current source reproduces it. See [UPSTREAM_ISSUE_REVIEW.md](UPSTREAM_ISSUE_REVIEW.md) for the full open-issue inventory. No proposed game fix is implemented without a reproducer.

The three most promising engine-wide investigations are P1-1 module closure, P1-2 GC/suspension and P1-3 executable-memory exceptions. Their breadth is a hypothesis; validate it with the initial target games and minimal test programs. Build work precedes deploying fixes.

For old store reports, current Mach code already includes STP writeback and STXR/STLXR handling. It explicitly lacks some LSE operations in that path; a separate POSIX path having an implementation does not prove Mach behavior is correct. Do not apply an old blanket decoder patch or disable fault limits. Reports involving modified Steam libraries must be reproduced with original legal game files and a generic memory test, without DRM workarounds.
